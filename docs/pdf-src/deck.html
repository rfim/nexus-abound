05 · Proving the lake

A check failed. The run fixed it.

No key can catch a row that never arrived. Only a comparison with the source can.

16 repayments rows didn't match Aurora

DMS delivered no repayments changes between 03:00 and 04:00 on 2026-09-20, the hour of the daily direct-debit run. The source has them, so the task resumed from the wrong position after an interruption: the rows are missing, not late.

Bronze had 0 changes in that hour, against a median of 10 on other days.

Fix: Reload repayments from the source (DMS 'reload table'), apply it as authoritative, re-run the reconciliation. Then alert on hourly change volume per table so a gap pages before a month-end report finds it.
src/nexus/silver.pya reload is authoritative
MERGE INTO lake.silver.repayments t
USING silver_batch s ON t.repayment_id = s.repayment_id
WHEN MATCHED AND s.change_seq > t.change_seq
  THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *
WHEN NOT MATCHED BY SOURCE AND NOT t.is_deleted
  THEN UPDATE SET t.is_deleted = true

After the reload: 18/18 checks pass, including reconciliation on every table.

06 · Speed, freshness and cost

Read only what you need

Athena bills bytes scanned at $5 per TB. The same queries, planned from Iceberg's own file statistics on three layouts.

QueryNaive (unpartitioned)months(booked_at)+ sorted, compactedLess scanned
Data Science: one customer's last 90 days578 KB · 72/221 files254 KB · 5/1855 KB · 3/7090%
Reporting: every transaction in September237 KB · 28/221 files52 KB · 2/1854 KB · 3/7077%

Hidden partitioning

months(booked_at): queries filter on the column, and the spec can evolve without a rewrite.

Sort order

WRITE ORDERED BY customer_id, booked_at: min/max bounds prune files for per-customer reads.

Maintenance

rewrite_data_files after MERGE; expire_snapshots and remove_orphan_files keep storage honest.

At Lifepal the same ideas, on Delta (partition pruning, Z-ordering, compaction, AQE), cut the nightly batch from 6 h to 90 min.

Point in time, or a leak

Open Banking enrichment relabels salary credits days after the fetch. A feature built from today's labels differs for 72 of 111 decisions, adding £2,807 of income on average that the model never saw.

At Lifepal: feature pipelines behind the customer-risk and claims-fraud models: point-in-time training sets, training/serving parity, drift monitoring and recalibration.

08 · Governance and erasure

Standards that run as code

Quality rules from the contract, reconciliation, freshness and erasure: checked on every run, failing loudly.

Contracts

contracts/sources.yml: keys, types, PII columns, what to reconcile. quality.yml: the rules on silver.

Erasure

Deletes become tombstones with values nulled; bronze is purged; expire_snapshots on 10 tables so time travel can't recover PII.

Freshness

Measured on a table that changes every day; in production, the DMS heartbeat and CDCLatencySource.

At Lifepal: 500+ quality checks in CI, freshness and volume monitoring with alerting, PII masking, role-based access and lineage. Data-trust escalations fell by 60%.
