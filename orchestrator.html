Every rule. Checked on every run.

02 · The incidentinvestigate → reload → recheck

A check failed. The run investigates.

The investigation step looks where a person on call would: which rows differ, when the source changed them, and whether bronze has any change from that hour. Then it reloads the table and checks again.

The keys it found


        
The fix, in src/nexus/silver.py


MERGE INTO lake.silver.repayments t USING silver_batch s ON t.repayment_id = s.repayment_id
  WHEN MATCHED AND s.change_seq > t.change_seq THEN UPDATE SET *
  WHEN NOT MATCHED THEN INSERT *
  WHEN NOT MATCHED BY SOURCE AND NOT t.is_deleted      -- a reload is authoritative
    THEN UPDATE SET t.is_deleted = true

    

  






  

    
03 · On a scheduleinfra/terraform/main.tf

    
The same steps. On AWS.

      
On AWS the batches become an hourly Glue job, and the rarer steps become their own runs, chained by Step Functions.

    

      
Hourly · Glue trigger
cron(10 * * * ? *)
Land new DMS files to bronze, apply them to silver, and run the quality rules. A failing rule fails the job.

      
Nightly
Reconcile, then gold
Reconciliation against an Aurora read replica, then the history tables, the calibration set and the loan book.

      
On failure
Investigate → reload
A Lambda posts the failing keys to on-call. The reload runs as a one-off Fargate task, then the checks run again.

      
Weekly
Compact and expire
rewrite_data_files, expire_snapshots and remove_orphan_files, with erasure requests applied first.
